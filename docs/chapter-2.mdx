# Chapter 2: ROS 2 Fundamentals

This chapter introduces the Robot Operating System 2 (ROS 2), the foundational software framework for modern robotics. Understanding ROS 2 is essential for anyone serious about developing sophisticated robotic applications.

## What is ROS 2?

ROS 2 is an open-source, flexible framework for writing robot software. It is not an operating system in the traditional sense, but a set of software libraries and tools that help you build robot applications. It provides services you would expect from an operating system, including hardware abstraction, low-level device control, implementation of commonly-used functionality, message-passing between processes, and package management.

ROS 2 is a complete overhaul of ROS 1, designed to address the needs of commercial and mission-critical applications. Key improvements include:

-   **Real-time support**: For applications requiring precise timing and control.
-   **Multi-platform**: Supports Linux, macOS, and Windows.
-   **Improved security**: Provides robust security features for authentication, encryption, and access control.
-   **Support for small embedded systems**: Can run on microcontrollers.

## Core Concepts

ROS 2 applications are typically structured as a collection of independent **nodes** that communicate with each other. This modular design makes systems easy to debug, reuse, and scale. The main communication patterns are:

### Nodes

A **node** is the smallest computational unit in ROS 2. It's a process that performs a specific task, such as controlling a motor, reading a sensor, or planning a path. Each node can be written, compiled, and run independently.

### Topics

**Topics** are named buses over which nodes exchange messages. They are the primary mechanism for one-way, anonymous communication. A node can **publish** messages to a topic, and any number of nodes can **subscribe** to that topic to receive the messages. This is a publish/subscribe model.

### Services

**Services** are used for two-way, request/reply communication. One node acts as a **service server**, providing a specific service, while another node acts as a **service client**, calling that service. Unlike topics, services are synchronous and execute a remote procedure call.

### Actions

**Actions** are for long-running, feedback-driven tasks. They are similar to services but provide feedback on the task's progress and allow the client to preempt the task. This is ideal for tasks like navigation, where it's important to know how the task is progressing.

## Setting up a ROS 2 Workspace

A ROS 2 workspace is a directory containing your ROS 2 packages. Here's how you typically set one up:

1.  **Create a directory**: `mkdir -p ~/ros2_ws/src`
2.  **Clone your packages**: `cd ~/ros2_ws/src` and clone your source code here.
3.  **Build the workspace**: `cd ~/ros2_ws` and run `colcon build`.
4.  **Source the setup file**: `source ~/ros2_ws/install/setup.bash`.

## Creating a Simple Publisher and Subscriber

Let's illustrate these concepts with a simple Python example of a node that publishes a "Hello World" message and another that subscribes to it.

**Publisher (`talker.py`):**

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher_ = self.create_publisher(String, 'topic', 10)
        timer_period = 0.5  # seconds
        self.timer = self.create_timer(timer_period, self.timer_callback)
        self.i = 0

    def timer_callback(self):
        msg = String()
        msg.data = f'Hello World: {self.i}'
        self
.publisher_.publish(msg)
        self.get_logger().info(f'Publishing: "{msg.data}"')
        self.i += 1

def main(args=None):
    rclpy.init(args=args)
    minimal_publisher = MinimalPublisher()
    rclpy.spin(minimal_publisher)
    minimal_publisher.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

**Subscriber (`listener.py`):**

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class MinimalSubscriber(Node):
    def __init__(self):
        super().__init__('minimal_subscriber')
        self.subscription = self.create_subscription(
            String,
            'topic',
            self.listener_callback,
            10)
        self.subscription  # prevent unused variable warning

    def listener_callback(self, msg):
        self.get_logger().info(f'I heard: "{msg.data}"')

def main(args=None):
    rclpy.init(args=args)
    minimal_subscriber = MinimalSubscriber()
    rclpy.spin(minimal_subscriber)
    minimal_subscriber.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

This simple example demonstrates the power of the ROS 2 framework for building modular and communicative robotic systems.
